# Архитектура kns-calculator

**Версия:** 0.1 | **Дата:** 2026-05-02

---

## Принципы

1. **Простота входа > точность модели на L0.** Менеджер не инженер — он не должен вводить шероховатость трубы и коэффициенты местных сопротивлений.
2. **Прогрессивное раскрытие.** L0 (4 поля) → L1 (+6 опционально) → L2 (30+ для инженера).
3. **Нейтральность подбора.** Калькулятор не продвигает один бренд — выдаёт 3 варианта в трёх ценовых сегментах.
4. **Hand-off, а не финальное решение.** L0-результат — это первичное предложение менеджера, не подмена работы инженера.
5. **Открытый датасет, открытая методология.** MIT-лицензия, формулы из публичных норм РФ.

## Алгоритм подбора (L0)

```
1. ВХОД: Q (м³/ч), dH (м), L (м), wastewater_type ∈ {domestic, drainage, industrial}

2. РАСЧЁТ:
   2.1. D_напор = подбор по v_target=1.2 м/с из стандартного ряда
   2.2. v_actual = 4·Q/(π·D²)
   2.3. Re, λ — Альтшуль
   2.4. H_тр = λ·L/D·v²/(2g)
   2.5. H_м  = 0.15·H_тр  (или 2.0 м фикс если L=0)
   2.6. H_full = (dH + H_тр + H_м) × 1.10

3. ФИЛЬТР ПО ТИПУ СТОКОВ:
   - domestic   → free_passage ≥ 50 мм, vortex/single-channel/multi-channel
   - drainage   → free_passage ≥ 10 мм, любое
   - industrial → free_passage ≥ 80 мм, vortex/cutter

4. Q-H ENVELOPE MATCHING:
   Кандидат проходит, если:
     Q ∈ [Q_min·0.85, Q_max·1.15]  AND
     H_full ∈ [H_min, H_max·1.05]   AND
     wastewater_type ∈ pump.wastewater_compat AND
     pump._engineer_flag != 'not_recommended'

5. РАНЖИРОВАНИЕ В КАЖДОМ ЦЕНОВОМ СЕГМЕНТЕ:
   composite_score = 0.40·BEP_proximity
                   + 0.25·eta_at_op
                   + 0.20·H_margin_quality
                   + 0.10·ru_availability
                   + 0.05·warranty

6. ВЫХОД: топ-1 в каждом из {budget, mid, premium}
```

Полная спецификация — `01_spec/matching.md` (в работе).

## Структура hand-off пакета

Каждый L0-расчёт генерирует **3 артефакта**:

1. **PDF-опросник клиенту** — структура полей по эталону `характеристики_КНС.png`. Поля автозаполнения из L0/L1, остальные — для уточнения у клиента.
2. **BOM-черновик** — позиции обвязки КНС/СПД с ориентировочными ценами. По 3 сегментам.
3. **JSON-payload для CRM** — машинно-читаемый блок: входы, расчётные параметры, выбранные модели, статус, ссылки на PDF.

Подробнее — `01_spec/handoff.md` (в работе).

## Дизайн-решения

### ❌ Что НЕ делаем (и почему)

- **Не делаем NPSH-расчёт для погружных КНС** — насос всегда «под заливом», NPSH не лимитирует
- **Не подбираем D = DN насоса** — даёт скорость 2.5+ м/с, износ труб
- **Не показываем cutter (измельчитель) для гостиниц/ТРЦ** — ножи не справляются с волокнами
- **Не используем чугунные трубы по умолчанию** — морально устаревшее решение
- **Не закладываем запас по напору 5%** — опасно мало; default 10%, для длинных трасс — 15-20%

Полный список 11 анти-паттернов — `02_dataset/ENGINEER_NOTES.md` раздел NOT_OK.

### ✅ Что подтверждено как рабочее

- Дарси-Вейсбах + Альтшуль для турбулентного режима в напорных трубах
- Q-H envelope matching ±15% / ±5% для первичного подбора
- 3 ценовых сегмента (Бюджет/Средний/Премиум) с фиксированными брендами
- Эталон верификации: KAIQUAN 50WQ/S 20-22-3 (проект АртВинд Мысхако, реальный)

## Тестовый кейс (smoke-check)

Это **НЕ эталон верификации** — для настоящей верификации нужен калибровочный
набор из десятков размеченных кейсов. Текущий тест — smoke-проверка, что
алгоритм даёт разумный результат на типовом входе.

Алгоритм возвращает KAIQUAN 50WQ/S 20-22-3 (фигурирует в реальном проекте
АртВинд Мысхако) при входе:
- Q = 21.2 м³/ч
- dH ≈ 10 м
- L ≈ 0 (компактная КНС внутри корпуса)
- wastewater_type = domestic

Если не попадает — это сигнал пересмотреть веса composite_score или БД насосов.

Seed-запись — `02_dataset/pumps/seed_kaiquan_50WQS202.json`.
