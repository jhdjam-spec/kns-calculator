## Как контрибьютить датасет

### Если вы добавляете насос

1. Откройте `02_dataset/pumps/pumps.json`
2. Используйте **схему** из `02_dataset/pumps/schema.json`
3. **Обязательно** заполните `_engineer_flag`:
   - `ok` — данные из паспорта производителя, проверены
   - `needs_review` — оценочные данные, требуется проверка
   - `not_recommended` — модель в БД для полноты, но не подходит для подбора
4. Укажите `_source` — откуда взяли данные (URL паспорта)
5. Если `_engineer_flag != "ok"` — добавьте `_engineer_note` с пояснением

### Если вы добавляете коэффициент

`02_dataset/theory/coefficients.json`:
- Все таблицы должны иметь `_source` (URL первоисточника)
- Если значение литературное / косвенное — добавьте `_engineer_note`
- Численные диапазоны: `{"min": ..., "max": ..., "default": ...}`

### Если вы исправляете формулу

`02_dataset/theory/formulas.md` — каждая формула снабжена меткой:
- ✅ рабочая
- ⚠️ с оговорками
- ❌ не подходит

При изменении метки — обоснуйте в pull request.

## Что НЕ публиковать в репозитории

- ❌ Реальные имена клиентов / контрагентов / контакты
- ❌ Шифры реальных проектов
- ❌ Внутренние цены конкретных дилеров (только публичные / усреднённые)
- ❌ Полные тексты СП и ГОСТ — **только ссылки на первоисточники**
- ❌ Q-H кривые в виде картинок производителей с копирайтом — только агрегированные данные (envelope) или реверс-инжиниринг через `WebPlotDigitizer` с пометкой `_source`

## Code style (когда дойдём до кода)

- Python: PEP 8, type hints, ruff/black
- TypeScript: ESLint + Prettier, strict mode
- Коммиты: conventional commits (`feat:`, `fix:`, `docs:`, `chore:`)
- Pull requests: ссылка на issue, краткое описание, тесты для нового кода

## Issues

Шаблоны:
- 🐛 **Bug:** что не работает + ожидаемое поведение + воспроизведение
- ✨ **Feature:** что добавить + зачем + кейс
- 📊 **Dataset:** какой бренд / норматив / коэффициент + источник + готов ли парсить сами
- ❓ **Question:** обсуждение архитектурных решений

## Лицензионная совместимость

MIT — совместима с большинством open-source лицензий. Если вы заимствуете код из других проектов:
- ✅ MIT, Apache-2.0, BSD — OK, сохранить копирайт
- ⚠️ GPL/AGPL — НЕЛЬЗЯ напрямую (lazy-link через CLI допустим)
- ⚠️ EUPL — обсуждать в issue (есть в EPyT — нужна осторожность)

Спорные моменты — обсудим в issue.
