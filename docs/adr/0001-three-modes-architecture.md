# ADR-001: Архитектура трёх режимов работы калькулятора

**Дата**: 2026-05-08
**Статус**: Принят
**Заказчик**: Серво-Юг (Константин Морозов)

## Контекст

Калькулятор КНС/НС/ливневок должен обслуживать **три аудитории с принципиально
разным уровнем подготовки**:

1. **Менеджер тендерного отдела / сметчик / заказчик с одной строкой ТЗ** — не
   знает что такое «напор», не знает СП 32, нужна оценка для бюджета.
2. **Инженер ПТО / ГИП проектной организации** — знаком с СП, нужны формулы и
   ссылки, готовит расчётную записку.
3. **ГИП крупного объекта / эксперт-консультант** — нестандартные условия (ATEX,
   УХЛ1, морской климат, Газпром СТО), защита в Главгосэкспертизе.

Один интерфейс на всех — либо отпугнёт менеджера сложностью, либо разочарует
эксперта примитивностью. Решение: **режимы работы**.

## Решение

### Три режима — это разные UI/UX и разный язык, не разный движок

Расчётное ядро (`pump_calculator.*`) — единое. Различаются:

| Параметр | Минимальный | Классический | Продвинутый |
| --- | --- | --- | --- |
| Аудитория | Менеджер, сметчик | Инженер ПТО (3+ года) | ГИП, эксперт |
| Полей ввода | 3-5 | 15-25 | 60+ |
| Время заполнения | 1-2 мин | 10-15 мин | 30-60 мин |
| Дефолтов | 90% от БД | 30% от БД | 0% (всё явно) |
| Output | 1 стр PDF (бюджет) | 5-10 стр (расчётка) | 20+ стр + Excel |
| Допуск точности | ±30% | ±15% | ±5% |
| Селектор СП 32 | Скрыт (всегда 2018) | Виден, дефолт 2018 | Параллельно 2012+2018 |
| Валидация input | Жёсткая | Мягкая (warning) | Только формальная |
| Кнопка «не знаю» | Есть на каждом поле | Только на сложных | Нет |
| Доступ | По умолчанию для гостей | По кнопке «Я инженер» | По кнопке «Эксперт» |

### Прогрессивное раскрытие, не жёсткие режимы

Это **один калькулятор с уровнями детализации**, не три отдельных приложения.

- На любом этапе можно «эскалировать»: «нажми сюда → увидишь больше параметров».
- Без потери уже введённых данных.
- При переходе вверх — все скрытые параметры показываются с пояснением «откуда
  взялось это значение по умолчанию».
- При переходе вниз — лишние параметры скрываются, но сохраняются в state.

### Tutorial-mode внутри Минимального

Менеджер не знает терминологии. Рядом с каждым полем — иконка ❓ → всплывает
объяснение **на бытовом языке** + картинка.

Пример: «Напор — это на сколько метров вверх насос должен поднять воду. Если
КНС стоит в подвале и сбрасывает на 1-й этаж — это ~3 м.»

### Smart defaults с обоснованием

В Минимальном режиме скрытые параметры подставляются **с пояснением в отчёте**:
«Для жилого дома 100 чел. принят K_общ=1.5 (СП 30 табл.5)».

Если инженер потом перейдёт в Классический — он увидит откуда взялись эти
числа и сможет переопределить.

### «Не знаю» — first-class citizen

В Минимальном у каждого поля кнопка **«не знаю»**. Тогда:

1. Берётся типовое значение из БД (по типу объекта + городу).
2. Поле подсвечивается жёлтым.
3. В отчёте добавляется строка: «Параметр X не указан, принят по умолчанию Y.
   Уточнить у инженера.»

### Output подстраивается под аудиторию

Один расчёт — три разных PDF:

- **Менеджеру**: 1 стр, цены крупно, картинки, без формул.
- **Инженеру**: 5-10 стр, формулы, графики, без воды.
- **Эксперту**: 20+ стр, все коэффициенты обоснованы, ссылки на пункты СП,
  чувствительность, сравнение редакций.

### Защита от «менеджер влез в продвинутый режим»

- Минимальный → Классический: свободно.
- Классический → Продвинутый: предупреждение «Этот режим для инженеров.
  Продолжить?»

### История пользователя

Если человек один раз заполнил Классический — при следующем заходе калькулятор
**сразу** открывает Классический. Менеджеру повторно «вводный режим» не
показываем.

### Без авторизации — публичный opensource

Калькулятор находится **в открытом доступе**, авторизации нет. Все режимы доступны
любому посетителю. Это решение принято намеренно:
- Снимает барьер входа для менеджеров и заказчиков.
- Соответствует opensource-философии (Apache-2.0).
- Авторство защищается **подписью INSERVO** (см. ADR-002), а не auth-стеной.

Дефолт режима для гостя — **Минимальный**. Переключение на Классический/Продвинутый
кнопкой «Я инженер» / «Эксперт». Состояние сохраняется в localStorage.

## Отраслевые шаблоны (ортогональная ось)

Шаблон выбирается **до** режима — он диктует:

- Какие поля скрыты/обязательны
- Какие дефолты подставляются
- Какие валидации включены (например ATEX-проверки для АЗС)
- Какой шаблон опросника производителя

Список:

| Иконка | Шаблон | Особенности |
| --- | --- | --- |
| 🏠 | Бытовой ИЖС | 5-50 чел, упрощённый flow Pedrollo/JETEX |
| 🏢 | МКД / коттеджный посёлок | СП 30, неравномерность по нормам |
| 🏪 | Магазин / ресторан / автомойка | Жироуловитель, нормы сброса |
| 🏭 | Промышленный | Под-категории: фильтрат ТКО, нефть, химия |
| 🌧️ | Ливневая | Парковки, дороги, кровли (СП 32 §6) |
| ⛽ | АЗС / нефтебаза | ATEX обязательно (IIB-T3) |
| ⛏️ | Карьер / шахта | Абразив, износ, частая замена |
| 🚢 | Морской объект | УХЛ1+М1, нерж. сталь, УГВ=уровень моря |
| 🏗️ | Газпром СТО | ABB AC500, HART, -47°C, премиум-требования |

Каждый шаблон **сам подбирает дефолты** для всех 3 режимов.

- Менеджер выбирает «🏠 ИЖС» → 3 простых поля.
- Инженер выбирает «⛽ АЗС» → автоматически включаются ATEX-проверки.

## Последствия

### Позитивные

- Один калькулятор для всех аудиторий → не плодим продукты.
- Менеджер получает быстрый бюджет без необходимости звать инженера.
- Инженер не утопает в простоте — может включить экспертный режим.
- Ясная защита от «менеджер вбил без проверки» (баннер beta + дисклеймер).
- Output разный по детализации → одна и та же логика, разные PDF-шаблоны.

### Негативные / риски

- Тройная работа над UI — каждое поле/виджет нужен в трёх вариациях.
  *Митигация*: одна форма с feature-flags `mode === 'minimal'`, не три отдельных.
- Smart defaults могут увести менеджера от правильного ответа. *Митигация*:
  баннер beta везде; в отчёте явно перечисляются все принятые «по умолчанию»
  значения с пометкой «требует уточнения у инженера».
- Сложно поддерживать соответствие отраслевых шаблонов нормам — нужна периодическая
  ревизия. *Митигация*: каждый шаблон — отдельный JSON-файл в `02_dataset/templates/`,
  рядом с справочниками насосов; ревизия раз в полгода.

### Открытые вопросы

- Когда вводить Личный кабинет (требуется для history per user)? — Не сейчас,
  Phase 5+.
- Как отличать «инженерный email» от внешнего без авторизации? — Никак на этом
  этапе. Дефолт = Минимальный для всех гостей; переключение на Классический
  кнопкой «Я инженер».

## План внедрения

1. **Phase 18.1** (текущая): калибровка ливневок до ±15%. Без этого Минимальный
   режим выдаст менеджерам неверные числа.
2. **Phase 19**: Минимальный режим для ливневок (4 поля → 1 стр PDF) как
   proof-of-concept механики режимов.
3. **Phase 20** (после нового массива данных от заказчика): Классический режим
   для КНС бытовых стоков.
4. **Phase 21**: Отраслевые шаблоны (ИЖС/МКД/АЗС/Промышленный/Морской/Газпром).
5. **Phase 22**: Продвинутый режим (М70098-уровень).
6. **Phase 23+**: Личный кабинет, роли, история.
