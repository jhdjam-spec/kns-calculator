# ADR-002: Подпись авторства INSERVO Studio

**Дата**: 2026-05-08
**Статус**: Принят
**Заказчик**: Серво-Юг (Константин Морозов)

## Контекст

Калькулятор публикуется как **opensource-проект** (MIT) без авторизации
пользователей. При этом он представляет результат работы Студии интеграции
умных решений Константина Морозова (INSERVO) и должен:

1. Узнаваемо сообщать об авторстве везде, где встречается с пользователем.
2. Сохранять подпись даже если код будет форкнут или встроен в другие системы.
3. Превращать каждый сгенерированный документ в маркетинговый канал автора.

Полная техническая «неудаляемость» в opensource невозможна — любой может
форкнуть и удалить. Но можно сделать удаление **юридически и технически крайне
неудобным**.

## Решение: многослойная подпись

Подпись внедряется на **6 уровнях** одновременно. Удалить все шесть — равно
переписать существенную часть кода.

### Слой 1. Публичный footer на сайте

Компонент `<Signature/>` в `Layout.tsx`. Не условный рендер, не feature-flag —
жёстко прибит к каркасу страницы.

```text
INSERVO · Студия интеграции умных решений Константина Морозова
inservo.ru · MIT · © 2026 K. Morozov
v0.X.Y · build {sha}
```

Под ним — короткий девиз (художественная подпись):

```text
«Каждая КНС — как картина: всё точно, ничего лишнего.»
```

### Слой 2. Подпись в каждом API-ответе

Backend всегда возвращает поле `_signature` верхнего уровня:

```json
{
  "_signature": {
    "studio": "INSERVO — Студия интеграции умных решений Константина Морозова",
    "author": "Konstantin Morozov",
    "url": "https://inservo.ru",
    "license": "MIT",
    "watermark": "K.M. © 2026"
  },
  "result": { ... }
}
```

Реализуется на уровне FastAPI middleware — все routes автоматически. Чтобы
скрыть, нужно отключить middleware и переписать каждый endpoint.

### Слой 3. Подпись в PDF/DOCX (главное для маркетинга)

Расчётные записки распространяются по тендерам и проектным организациям —
это основной канал «органического» распространения авторства.

В каждом сгенерированном документе:

- **Колонтитул на каждой странице** (footer): _«Расчёт сгенерирован калькулятором
  INSERVO ([inservo.ru](https://inservo.ru))»_
- **Шапка титульной страницы**: логотип INSERVO + полное наименование студии.
- **Последняя страница**: блок _«О студии»_ с контактами, описанием услуг,
  QR-кодом на сайт.
- **Метаданные PDF** (`/Author`, `/Producer`, `/Creator`, `/Title`,
  `/Subject`, `/Keywords`): зашита подпись на машинном уровне (видно через
  `pdfinfo` любому, кто проверит).
- **Невидимый watermark**: на каждой странице полупрозрачный текст «INSERVO»
  под основным контентом (CSS opacity 0.04 для HTML, прямой вотермарк в PDF).

### Слой 4. Подпись в исходном коде

Заголовок-копирайт в каждом значимом исходнике (Python, TypeScript, конфиги):

```python
# ╭──────────────────────────────────────────────────────────────────────╮
# │ INSERVO Studio — Калькулятор подбора КНС/НС/ЛОС                      │
# │ Автор: Константин Морозов · https://inservo.ru                   │
# │ Лицензия: MIT (см. LICENSE и NOTICE)                                 │
# │ Просьба сохранять авторство при использовании производных работ      │
# ╰──────────────────────────────────────────────────────────────────────╯
```

В корне репозитория:

- `LICENSE` — MIT License с copyright «© 2026 Konstantin Morozov · INSERVO Studio».
  MIT обязывает сохранять copyright notice при любом производном использовании.
- `NOTICE` — добровольный файл с подписью студии (не требуется MIT, но
  публикация подчёркивает авторство и упрощает атрибуцию в производных).
- `README.md` — Authors-блок в самом верху, Studio-блок в конце.
- `AUTHORS` — список авторов в свободной форме (для гитхаба).

### Слой 5. Скрытая подпись («водяной знак художника»)

Это «подпись на холсте под краской» — то, что сохранит авторство даже после
поверхностного rebrand'а форка.

Реализация:

1. Константа `__signature__ = "INSERVO/KM-2026"` в каждом значимом модуле.
2. Тесты `test_signature_present` проверяют наличие константы. Если кто-то
   удалит её ради чистки — тесты упадут, форк станет «не работающим без
   починки». Чинить = либо вернуть подпись, либо переписать тесты (явное
   действие, фиксируется в git-истории форка).
3. В `__init__.py` пакета `pump_calculator` поля `__version__`, `__author__`
   = `"Konstantin Morozov · INSERVO Studio"`, `__license__` = `"MIT"`,
   `__url__` = `"https://inservo.ru"`.
4. В сгенерированных JSON-результатах последний знак расхода `Q_r_l_s`
   модулируется детерминированным микро-шумом, кодирующим `KM2026`.
   Невидимо для пользователя (3-й знак после запятой), но при сличении двух
   расчётов с одинаковыми входами оригинал и форк выдают РАЗНЫЕ числа —
   это **криптографическое доказательство авторства**.

  > Внимание: эту фичу включаем **только** после публичного запуска и только
  > если она проходит ревью на «не вредит инженерной точности». Если ±15%
  > коридор — модуляция в 4-м знаке невидима. Если коридор сужается до ±5%
  > для Продвинутого режима — модуляцию отключаем для этого режима.

### Слой 6. Подпись в UX-механике (artisan-touch)

Каждые N расчётов (или 1 раз в сессию) в нижнем правом углу на 3 секунды
появляется аккуратная анимация подписи INSERVO. Не интрузивно, не блокирует
интерфейс. Запоминается как «характер инструмента» — как стиль художника
узнаётся даже без прямой подписи.

## Юридическая защита

- **Apache License 2.0** даёт право свободного использования, но **§4(a)** и
  **§4(d)** обязывают сохранять `NOTICE` и подпись в производных работах.
- Удаление подписи — формальное нарушение лицензии, основание для иска.
- В `README.md` явная фраза: _«Этот проект — авторская работа. Использование
  разрешено по MIT. Удаление подписи в footer / PDF / API нарушает §4(a)
  лицензии и преследуется по закону.»_
- Регистрация словесного знака «INSERVO» — отдельная задача (Phase 25+).

## Принятые формулировки

**Полная подпись** (для NOTICE, LICENSE, README, footer):

> Разработано и реализовано Студией интеграции умных решений Константина Морозова
> (INSERVO Studio, [inservo.ru](https://inservo.ru)).

**Короткая подпись** (для PDF-колонтитула, API _signature):

> INSERVO · K. Morozov · MIT © 2026

**Художественная подпись-девиз**:

> Каждая КНС — как картина: всё точно, ничего лишнего.

Альтернативные девизы (на согласование):

- _Цифры, которым доверяют инженеры._
- _Каждый расчёт — авторская работа._
- _От гидравлики до тендера — за 5 минут._

## Последствия

### Позитивные

- Узнаваемое авторство во всех артефактах.
- Каждый PDF, разосланный по тендерам, — точка контакта со студией.
- Юридический рычаг (Apache §4) защищает от форков с удалённой подписью.
- Скрытая подпись (Слой 5) даёт криптографическое доказательство авторства.
- Не мешает opensource-философии — проект остаётся свободным для
  использования и модификации (с сохранением подписи).

### Негативные / риски

- Легальный форк может прибрать подпись (нарушив лицензию). _Митигация_:
  отслеживать форки на github, при обнаружении нарушений — DMCA / претензия.
- API-поле `_signature` увеличивает размер ответа (~200 байт). _Митигация_:
  пренебрежимо мало для JSON.
- Микрошум в значениях (Слой 5) теоретически может смутить инженера, который
  «увидит лишний знак». _Митигация_: модуляция только в незначащих знаках,
  явно описанная в публичной документации.

## План внедрения

1. **Phase 19**: Слои 1, 2, 4 (footer + API _signature + копирайты в исходниках).
   Это прибивается к каркасу — сделать ДО первого публичного запуска.
2. **Phase 20**: Слой 3 (PDF/DOCX подпись) — одновременно с PDF-генератором.
3. **Phase 21**: Слой 5 (скрытая подпись `__signature__` + тесты).
4. **Phase 22**: Слой 6 (UX artisan-touch).
5. **Phase 25+**: регистрация товарного знака INSERVO.
