# Выпуск frontend на Beget

Backend CI и Frontend CI проверяют изменения в GitHub. Workflow **Beget frontend release** вручную запускается для `main`, повторяет проверки frontend и передаёт на VPS только статическую сборку. API на Beget остаётся отдельным сервисом. Сборка обращается к API через `/api/backend`.

## Подготовка сервера администратором

1. Создайте отдельного пользователя `podborkns-deploy` без sudo и доступа к Docker. Установите `publish_frontend.py` как `/usr/local/sbin/podborkns-publish` с владельцем root и правами 0755.
2. Создайте `/opt/podborkns/public/.releases`. Скопируйте текущую рабочую статику в `initial` внутри этого каталога, исключив сам каталог `.releases`. Проверьте `initial/index.html` и создайте относительную ссылку `current → initial`. Каталог `.releases` принадлежит `podborkns-deploy`. Его родитель доступен на запись только администратору.
3. В Caddyfile контейнера `podborkns-web` замените корень статики с `/srv` на `/srv/.releases/current`, оставив обработчик API. Проверьте конфиг и перезагрузите только этот Caddy. Проверьте главную, страницу проекта и `/api/backend/health`.
4. Создайте отдельную пару ключей Ed25519 для этого workflow. В `authorized_keys` пользователя добавьте публичный ключ с ограничениями `restrict,command="/usr/local/sbin/podborkns-publish"`. Закройте пользователю возможность писать в свою конфигурацию SSH. Приватный ключ храните только в GitHub Secrets и в администраторском хранилище при необходимости.

## Настройки GitHub

Создайте environment `beget-production` и ограничьте разрешённые ветки веткой `main`. Укажите переменную `BEGET_HOST` и два секрета `BEGET_KNOWN_HOSTS`, `BEGET_DEPLOY_KEY`. Запись known_hosts должна быть сверена с доверенным ключом VPS. Приватный ключ должен соответствовать выделенной учётной записи.

После проверки коммита в `main` запустите workflow через **Actions → Beget frontend release → Run workflow**. Статус выпуска станет зелёным после проверки HTTPS, двух страниц и API со стороны Beget.

Публикация блокирует параллельные операции, проверяет хеш, отклоняет ссылки и пути за пределами архива и переключает каталог атомарно. При сбое проверки ссылка возвращается к предыдущей версии. Каталоги выпусков остаются на VPS; при обслуживании можно удалить старые невостребованные версии, сохранив активную и нужную для отката.

Первый запуск следует делать после попадания проверенной версии frontend в `main`. Workflow публикует содержимое выбранного коммита GitHub, поэтому локальные правки попадут в релиз после отдельного переноса в репозиторий.
