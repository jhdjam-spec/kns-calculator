# Инженерные пометки по датасету

**Версия:** 0.2 | **Дата:** 2026-05-03
**Changelog v0.2:** добавлено 12 новых NOT_OK (NOT_OK-12..23) из R3 deep-research. Закрыто 5 GAP по R1/R2.
**Принцип:** здесь собраны ВСЕ пометки «не подходит / нужна проверка / не работает» — единое место для контроля качества датасета.

Метки:
- 🟢 **OK** — данные проверены, можно использовать
- 🟡 **REVIEW** — данные оценочные / косвенный источник, нужна верификация
- 🔴 **NOT_OK** — данные не подходят / не работают / неприменимы для нашего сегмента
- ⚪ **GAP** — данных нет, надо собирать

## 🔴 Решения, КОТОРЫЕ НЕ РАБОТАЮТ

### 🔴 NOT_OK-01: Aquario / Belamos / Unipump для промышленных КНС
**Где:** `pumps/pumps.json::_NOT_RECOMMENDED`
**Причина:** бытовые насосы с малым ресурсом. В коммерческой нагрузке (~24/7) выходят из строя за 6-12 месяцев. **Включаем в БД, но в L0-подборе НЕ показываем** — только при явном запросе менеджера для мини-КНС частного коттеджа.

### 🔴 NOT_OK-02: Cutter (измельчитель) для гостиниц/ТРЦ
**Где:** `theory/formulas.md §9`
**Причина:** режущие ножи не справляются с волокнами/тряпьём, ломаются. **Только для частных коттеджей с длинной напоркой DN32-65 (>50 м).** Алгоритм должен исключать cutter при `wastewater_type=domestic AND N_users>20`.

### 🔴 NOT_OK-03: Чугун для напорной канализации (default)
**Где:** `theory/coefficients.json::pipe_roughness_mm`
**Причина:** морально устаревшее решение. Default — ПЭ100 SDR17. Чугун — только при реконструкции существующих сетей. Калькулятор НЕ предлагает чугун в L0.

### 🔴 NOT_OK-04: NPSH-расчёт для погружных КНС
**Где:** `theory/formulas.md §4`
**Причина:** погружной насос всегда «под заливом» — NPSH не лимитирует. Включаем NPSH-проверку **только для** СПД с поверхностной/сухой установкой.

### 🔴 NOT_OK-05: Запас по напору 5%
**Где:** `theory/coefficients.json::head_safety_factor`
**Причина:** слишком оптимистично. Минимум 10%, для длинных трасс 15-20%. На L0 фиксируем 10%.

### 🔴 NOT_OK-06: Подбор насоса по нижнему пределу диапазона производителя
**Где:** algorithm logic (будущее)
**Причина:** если Q_user≈Q_min насоса — КПД низкий, возможна кавитация. Алгоритм должен предпочитать модели где Q_user попадает в ±20% от Q_BEP.

### 🔴 NOT_OK-07: «Один насос на все типы стоков»
**Где:** algorithm logic
**Причина:** vortex с КПД 35% — норма для хоз-быта, но переплата 30%/год электричества для дождёвки. Сегментация обязательна.

### 🔴 NOT_OK-08: «Q без учёта H»
**Где:** algorithm logic
**Причина:** распространённая ошибка менеджеров. Калькулятор обязан считать H_full перед фильтрацией БД.

### 🔴 NOT_OK-09: Подбор D = DN насоса
**Где:** `theory/formulas.md §8`
**Причина:** даёт скорость 2.5+ м/с. Избыточные потери трения и износ. **D подбираем по v_target=1.2 м/с**, не по DN насоса.

### 🔴 NOT_OK-10: Cutter (измельчитель) с ШУ без плавного пуска
**Где:** algorithm logic
**Причина:** cutter имеет высокий пусковой момент. Без плавного пуска — нагрузка на сеть и быстрый износ. ШУ обязательно с плавным пуском или ЧРП.

### 🔴 NOT_OK-11: Шаровой обратный клапан DN>200
**Где:** `fittings/fittings_seed.json`
**Причина:** для больших DN шар становится тяжёлым, медленно срабатывает, гидроудары. Для DN>150 — поворотный или межфланцевый.

### 🔴 NOT_OK-12: Работа вне AOR (40-150% Q_BEP) — ANSI/HI 9.6.3
**Где:** algorithm logic, `coefficients.json::ansi_hi_963_operating_regions`
**Причина:** даже если насос «попадает в Q-диапазон производителя» — за пределами AOR ускоренный износ подшипников/уплотнений в 2-5 раз. POR (70-120%) обязателен для continuous работы.
**Проверка:** в матчинге фильтр AOR — жёсткий; POR — penalty в score.

### 🔴 NOT_OK-13: NPSH игнорируется при T>40°C даже для погружных
**Где:** `formulas.md §4`, dependencies_map DEP-34
**Причина:** при 60°C H_v=2 м, при 80°C H_v=5.4 м — NPSHa может стать отрицательным, кавитация даже на залитом насосе.
**Проверка:** для T>40°C — обязательный NPSH-расчёт + триггер hand-off.

### 🔴 NOT_OK-14: СПД с ΔP старт/стоп <0.5 бар
**Где:** `coefficients.json::spd_pressure_differential`
**Причина:** при малом разборе насос пускается каждые 5-10 секунд → сгорание мотора. Минимум 0.5 бар, рекомендуется 1.0-1.4 бар.

### 🔴 NOT_OK-15: Многоступенчатый СПД без soft-stop / surge-protection
**Где:** SPD logic
**Причина:** гидроудар по Жуковскому 30-50 м при отключении питания → разрыв труб у фланцев. Нужен ЧРП с ramp-down или surge-tank.

### 🔴 NOT_OK-16: ШУ без PTC/PT100 для погружных >5.5 кВт
**Где:** BOM-генератор, `coefficients.json::motor_protection_required`
**Причина:** без термозащиты обмоток мотор сгорает при первом cycling-инциденте или работе вне POR. Thermal_overload реагирует за 20 сек — поздно.

### 🔴 NOT_OK-17: ШУ без phase-monitor relay для трёхфазных >7.5 кВт
**Где:** BOM-генератор
**Причина:** reverse phase = вибрация и износ за часы; single-phasing = сгорание за 5-30 секунд. Phase_monitor отключает за 0.1-1 сек.

### 🔴 NOT_OK-18: Прямой пуск (DOL) >7.5 кВт
**Где:** `coefficients.json::motor_starting_method_by_power`
**Причина:** пусковой ток 150-200 А, провалы сети, износ контакторов, штрафы от энергосбыта. >22 кВт — soft-start обязателен; >75 кВт — только ЧРП.

### 🔴 NOT_OK-19: ПЭ-корпус с УГВ выше дна без anchoring SF≥1.25
**Где:** `coefficients.json::anchoring_safety_factor`, dependencies_map DEP-35
**Причина:** удельный вес HDPE 0.97 → всплывает при опорожнении на сервис (NPCA: SF≥1.10 норма, ≥1.25 для зон с УГВ).

### 🔴 NOT_OK-20: Зазор насос-стенка корпуса <100 мм
**Где:** `coefficients.json::pump_to_wall_clearance_mm`
**Причина:** нарушение cooling flow вокруг мотора → перегрев → срабатывание PTC каждые 20 минут → cycling-смерть. Без shroud нужна v_поток >0.5 м/с вдоль мотора.

### 🔴 NOT_OK-21: Длинная напорка с подъёмами (>100 м) без air release valves
**Где:** dependencies_map DEP-30
**Причина:** газ накапливается на high points, эффективное сечение падает, насос смещается влево по кривой, recirculation, перегрев.

### 🔴 NOT_OK-22: H/D корпуса >4
**Где:** `fittings/fittings_seed.json::corpus`
**Причина:** неудобный монтаж и обслуживание, риск опрокидывания при транспортировке. Default H/D ≤ 3.

### 🔴 NOT_OK-23: Нет проверки минимального run-time
**Где:** algorithm logic, `coefficients.json::pump_starts_per_hour_max::_min_run_time_seconds`
**Причина:** малые насосы должны работать минимум 1 мин/пуск; крупные (>55 кВт) — 5-10 мин. Меньшее время → cycling-смерть. Если расчётный V_приёмного даёт меньше — увеличить V.

### 🟡 REVIEW-07: Цены 2026 на обвязку
**Где:** `fittings/fittings_seed.json`

### 🟡 REVIEW-09: Auto-coupling ζ
**Где:** `theory/coefficients.json::local_resistance_zeta::auto_coupling_DN50_100`
**Что делать:** производители паспортов с ζ для АТМ обычно НЕ дают. Принято типовое 0.8 — может быть 0.5-1.5. Уточнять при следующей итерации.

### 🟡 REVIEW-10: Поправка плотности стоков для подбора насоса
**Где:** `theory/formulas.md §5`
**Что делать:** ρ=1010 vs 1000 → разница в N_вал ~1%. Возможно, на L0 пренебрегаем. Для L2 (инженер) — обязательно.

## Полный sanity-check для production-релиза

Перед публичным запуском калькулятора (release) **обязательно закрыть:**
- [x] OK-01..10 — уже работают
- [ ] REVIEW-04 (табл. 17 СП 32) — для юридической чистоты
- [ ] REVIEW-05 (K_gen) — для нормативной точности расчёта
- [ ] GAP-01 (Q-H кривые) — без них алгоритм даёт оценку, не подбор
- [ ] GAP-02 (А.2 СП 30) — для калькулятора «Q из норматива»
- [ ] GAP-10 (Серво-Юг корпуса) — без них BOM неполный

REVIEW-01..03 и GAP-03..09 — для перехода в режим L2 «Профессионал». На L0 калькулятор может работать с текущими дефолтами.
